# Dependabot 依赖更新审核

仓库的 `.github/dependabot.yml` 每周检查两组依赖，GitHub Dependabot 因此会自动提交 PR：

- `frontend`：前端构建依赖及 npm 锁文件。
- `official-actions`：GitHub Actions 的固定提交。

机器人提出升级建议后仍需审核、验证，再合并；CI 不自动发布新版本。

## 2026-11-08：PR #2 与 #3

[PR #2](https://github.com/fengwenhua/AD_Killer_By_NFQUEUE/pull/2) 将 Vite 8.3.4 升至 8.3.5、Rollup 4.59.0 升至 4.66.0，同时更新相应的平台包和传递依赖。前端运行库 Vue、GSAP 保持原版本。npm 按锁文件安装后，本地 92 项前端测试、离线单文件构建及完整 Python 契约组通过；合并当前 main 后重新跑 GitHub CI。

[PR #3](https://github.com/fengwenhua/AD_Killer_By_NFQUEUE/pull/3) 原先只更新工作流中的 SHA，没有同步 `.github/actions.lock.json`。失败日志明确指出 `actions/checkout must match the reviewed full SHA`；这是审核锁拦住了未经记录的升级，不能通过放宽断言处理。

已从各 Action 的官方仓库核对精确版本标签与固定提交，下载该提交的原始 `action.yml`，检查 Node.js 24 运行声明、所用输入及执行入口，并记录文件 SHA-256：

两个 PR 均已在完整 CI 通过后合并。合并后的 [main CI 42469894622](https://github.com/fengwenhua/AD_Killer_By_NFQUEUE/actions/runs/42469894622) 八项全部成功，完整耗时 8 分 51 秒；并行分组与原串行基线对照见 [CI 与模糊测试](CI与模糊测试.md)。

## 后续处理同类 PR

1. 核对 PR 作者、实际文件差异、上游发布说明及兼容性，不执行 PR 文本中附带的任意命令。
2. 前端依赖使用 `npm ci` 验证锁文件，运行前端测试和构建；由 CI 检查浏览器交互、Android 包及可复现性。
3. Actions 升级先核对官方标签与提交、读取新提交的 `action.yml`，再同步审核锁的 `sha`、`reviewed_ref`、`runtime` 和原始文件摘要，以及工作流版本注释。不因为机器人升级而删除审核锁校验。
4. 将当前 main 的改动纳入待合并分支，等待完整 CI 通过，再合并。依赖 PR 与模块公开发版分别处理。
