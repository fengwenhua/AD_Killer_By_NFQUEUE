# Dependabot 依赖更新审核

仓库的 `.github/dependabot.yml` 每周检查两组依赖，GitHub Dependabot 因此会自动提交 PR：

- `frontend`：前端构建依赖及 npm 锁文件。
- `official-actions`：GitHub Actions 的固定提交。

机器人提出升级建议后仍需审核、验证，再合并；CI 不自动发布新版本。

## 后续处理同类 PR

1. 核对 PR 作者、实际文件差异、上游发布说明及兼容性，不执行 PR 文本中附带的任意命令。
2. 前端依赖使用 `npm ci` 验证锁文件，运行前端测试和构建；由 CI 检查浏览器交互、Android 包及可复现性。
3. Actions 升级先核对官方标签与提交、读取新提交的 `action.yml`，再同步审核锁的 `sha`、`reviewed_ref`、`runtime` 和原始文件摘要，以及工作流版本注释。不因为机器人升级而删除审核锁校验。
4. 将当前 main 的改动纳入待合并分支，等待完整 CI 通过，再合并。依赖 PR 与模块公开发版分别处理。
