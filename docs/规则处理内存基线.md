# 规则处理内存基线与第一阶段优化

2026-10-26，O09 第一阶段。生产基线为 v1.2.7 对应实现；测量使用 Debian
arm64、Clang 14、`-O2` 严格编译、LinuxKit 6.12.72 的一次性容器。
结果不是 Android/Bionic、低内存机或新鲜网络下载的性能结论。

## 测了什么

`tests/integration/profile_rule_memory.py` 运行真实 CLI 的 `--update`、
`--daemon --foreground` 和 `--reload`，等待精确策略修订号 applied。
没有替换解析、合并、gzip、规则代际提交或守护加载实现。

下载后端在测试构建中指向不存在的路径，预先按真实来源身份、格式、SHA-256 和
完整组校验写入缓存；同步因此走真实的整组缓存回退路径。原始默认来源 URL 不被
替换成改变格式选择的假 URL。HaGeZi Pro/Fake 作为同一组预置，单源或依赖缺失
不能伪造成功。这是 **缓存同步重放**，未测量 TLS、在线下载缓冲或弱网耗时。

- 同步峰值为父进程 `wait4` 返回的内核 ru_maxrss，Linux 单位 KiB。
- 启动、重载读取目标守护的 VmHWM/VmRSS。重载前对同一 PID/启动时刻/映像
  核验后写入该受控测试进程的 clear_refs=5，单独记录重载 HWM。
- 启动和重载的回落值是到达 running/applied 后约 1 秒的 RSS；重载重建同一完整
  规则集合，仍经过新旧不可变快照并存的真实路径，没有故意减少旧快照保护。
- 不相加父子 fork/CoW RSS，不把向量逻辑容量冒充物理内存，也不清全机 page cache。
- 默认输入交错测量优化前/后各 3 次，表中报告中位数；压力场景各 1 次，不能据此
  声称精确的平均收益或耗电改善。

## 保留的实现

1. 去重排序使用指向原文本的 string_view，避免整份 istringstream 副本与每行
   字符串分配；按精确大小重建输出。不能原地覆盖尚未消费的重排视图。
2. 首个分类结果直接移交字符串所有权。gzip 把头和正文分段输入同一个流，
   不再为了加头复制整份规则；压缩后释放正文，staging 写完后释放压缩缓冲。
3. 完整验证后的私有 RuleSet 先排序压紧，再移交数组；保留 const 合并接口和
   exact/suffix、黑白名单、bad_lines 语义。试验发现“先移交多余容量，最后再
   压紧”会使大规则集 RSS 回退，最终实现已避免该路径。

原规则代际事务、坏 gzip/资源上限拒绝、回滚与旧快照并发保护保持原有约束。
这不是输入上限下调或 RSS 硬限制，也没有调用 malloc_trim 干预全进程分配器。

## 正确性与证据

三组输入的前后完整 Hosts/AdGuard gzip **逐字节一致**，规范行集合摘要和引擎
黑白类型计数一致。没有用“条数相同”替代完整产物对照。

默认来源另用独立 Python 参考实现核对：普通来源 243,626 条规范 AdGuard 行、
HaGeZi 差集 190,712 条精确 Hosts 行，跨分类合并后黑 427,058 / 白 75。
黑白、精确/后缀及 gzip 格式边界已有共享规则回归；新增测试覆盖空行、无尾换行、
CR/NUL 字节、重排覆盖风险、移动合并与旧版 gzip 的逐字节兼容。

## 复测

只在明确的一次性 Linux/root 环境执行，会创建并清理固定模块数据目录、建立
NFQUEUE 与路由。已有模块数据时拒绝运行，不用于手机卸载或生产环境清理。
需 Clang/C++17、zlib、Python 3、procps、iptables、conntrack 和 NFQUEUE 权限。

```sh
# 已有冻结默认快照：目录必须带 sources.tsv 和 benchmark-inputs.json。
# 清单记录每个原始文件的 file/url/format/bytes/sha256；内置双源为 paired-hosts。
MEMORY_SNAPSHOT=/path/to/snapshot MEMORY_OUTPUT=/tmp/default-memory-001 \
  CXX=clang++ make profile-rule-memory

# 可直接从源码重建的压力样本；每个来源最多 60 MiB，near-limit 创建 4 个来源。
python3 tests/integration/create_memory_inputs.py --case near-limit --output /tmp/near-input
python3 tests/integration/create_memory_inputs.py --case duplicates --gzip --output /tmp/duplicate-input
MEMORY_SNAPSHOT=/tmp/near-input MEMORY_OUTPUT=/tmp/near-memory-001 \
  CXX=clang++ make profile-rule-memory

python3 tests/integration/compare_memory_profiles.py /tmp/before /tmp/after
```

每次使用新的输出目录。未知守护退出或仍有写入者租约时保留现场，不报告完整成功；
已回收的测量子进程不会再被发信号。测试工具位于 tests/，临时目录只存构建与数据。
不自动升级手机、不调整正式版本号，也不作为自动发布的输入。
