# 兼容性与协议限制

## 支持矩阵

| 项目 | 支持范围 | 说明 |
|---|---|---|
| CPU / ABI | arm64-v8a | 产出 Android arm64 PIE；构建与 ZIP 验证器检查每个 LOAD 段至少 16 KiB 对齐 |
| Android | API 31（Android 12）及以上 | 二进制以 `aarch64-linux-android31` 编译；更低 API 未承诺兼容 |
| Root 管理器 | KernelSU、APatch；Magisk 基础服务 | 安装/服务脚本按三者通用接口编写；内置 WebUI 主要面向提供 `ksu.exec()` 的管理器 |
| IP | IPv4、IPv6 | 双栈 iptables 路由；IPv6 常见扩展头有界遍历 |
| 防火墙 | legacy/nft 后端的 `iptables`、`ip6tables` 命令接口 | 必须具备 mangle、owner、connmark、NFQUEUE、queue-bypass，以及 `iptables-save`/`ip6tables-save`；操作等待 xtables 锁最多 5 秒 |
| 内核 | NFQUEUE + conntrack + netfilter netlink | 必须支持 NFQA fail-open；连接标记使用 NFQA conntrack glue，缺失时要求独立 CTNETLINK 掩码更新接口。`--queue-bypass` 只覆盖无监听器，不能覆盖队列满或 userspace 投递失败 |
| 快速拒绝 | NET_RAW + IPv4/IPv6 RAW socket、HDRINCL | 启动前检查，只为已拦截的出站请求向本地发起者发送否定响应；不修改 SELinux 或系统 DNS 配置 |

以上为代码和主机端测试所覆盖的设计范围，不等于所有厂商 ROM 已完成设备认证。
发布前至少应在目标 ROM 上执行启动、双栈 DNS、HTTP/TLS、热重载、规则更新、停止
和异常杀进程测试；发布门禁与设备矩阵见[真机上线审计与验收方案](真机上线审计与验收方案.md)。

## 已知协议边界

- 只直接解析传统 UDP/TCP 53 DNS。DoH、DoT、DNSCrypt 和应用内自建加密 DNS 不会被
  当作 DNS 查询解析；它们可能仅在目标域名本身命中其它连接规则时受影响。TCP DNS
  支持乱序/重传、跨 segment 长度帧和单 segment 多查询，每流最多缓存 16 KiB；任一
  查询命中后会标记并阻断该 TCP 连接。
  对可安全处理的普通 UDP DNS 返回 NXDOMAIN（保留 ID 和 question 字节、
  清除 AD/答案与额外记录并重算校验和），再丢弃原查询。TCP DNS 命中时快速 reset
  本地连接。IP options/扩展头、截断或非法 DNS 不强行构造回答，按 fail-open 放行
  并计数；不把静默等待 DNS 超时作为默认拦截策略。
- HTTP 仅检查 TCP 80，TLS SNI 仅检查 TCP 443。未分类连接进入 queue 1；有界解析完成后
  以 `0xa4000000/0xfc000000`（阻断）或 `0xa8000000/0xfc000000`（放行）使用 connmark
  bit 26..31，后续包在队列前直接 DROP/RETURN，其余 26 位保持不变。该掩码避开
  AOSP netd 低 20 位网络状态和 bit 24/25 明文检测状态；接管前检查双栈全表外部
  connmark 读写冲突，失败时拒绝接管。这些位不是官方为第三方保留的命名空间，
  尚需目标 vendor/BPF 设备验收。每流握手缓存 16 KiB、全局 2 MiB、
  最多 1024 流、空闲超时 10 秒。
  支持 `CONFIG_NETFILTER_NETLINK_GLUE_CT` 未启用但 `CONFIG_NF_CT_NETLINK`
  和 `CONFIG_NF_CONNTRACK_MARK` 可用的内核：每队列独立 socket，先只读双栈探测，
  再以 CT_NEW（不带 CREATE/EXCL）和 CTA_MARK_MASK 更新已存在连接，等待内核 ACK
  后发送普通 verdict。连接已过期（ENOENT）只回复当前 verdict，不创建新连接；
  其它更新错误触发退出清理。协议依据见 [Linux CTNETLINK 实现](https://github.com/torvalds/linux/blob/v6.6/net/netfilter/nf_conntrack_netlink.c)。
- TLS Encrypted ClientHello（ECH）隐藏 SNI 后无法按目标站点域名判定。无 SNI、超大或
  无法在资源上限内连续重组的握手按 fail-open 原则标记放行并计数。
- QUIC/HTTP3 内容不解析。启用 QUIC 开关时 UDP 443 进入队列 1，返回 ICMP/ICMPv6
  端口不可达后丢弃原包，促使客户端及时回退 TCP；拒绝
  回退或使用其它 UDP 端口的应用可能不可用或绕过检查。
- IPv4/IPv6 真实分片不重组，首片和非首片均安全放行；IPv6 atomic fragment 可解析。
- 规则引擎只表达域名 exact/suffix 和白名单。URL 路径、请求类型、脚本、元素隐藏、
  正则表达式及带请求修饰符的 AdGuard 规则会被拒绝，不能等价替代浏览器内容拦截器。
- 热重载先构建私有候选；路由切换期间两条队列仍收包，但对送入队列的包临时
  ACCEPT，且不写 PASS/BLOCK 连接标记。双栈路由成功后发布新快照，等待两条接收
  socket 都观测到提交后的 EAGAIN，再恢复判定。切换窗口可能放过广告，并非无缝阻断；
  正常回滚保留旧快照、旧统计和旧重组缓存，回滚或收包边界无法确认则退出接管。
  ACK-only 帧、EINTR 或提交前的空闲观察都不算完成。该边界不代表 Linux 全部网络
  hook 的全局原子事务，也不追溯已回复的包。
- 已有 PASS/BLOCK connmark 保留至连接结束或内核过期，热重载不会全局清空 conntrack。
  已放行的 HTTP/TLS 连接可继续放行，即使新规则现在阻断该域名；请新建连接验证。
  用户态重组缓存仅在成功切换后清除，不能重新获取早已结束的 TLS ClientHello。
  CLI 的 `queued/deferred + revision` 只表示提交；可用 `--apply-status REVISION` 查询
  与当前守护启动身份绑定的回执。回执 `applied` 不是完整网络健康证明，还需
  `--status` 验证路由、进程和冻结状态。界面会有界观察本次修订号的 ACK，
  未确认、失败或被后续保存替代时不会提示已生效；概览显示保留的实际策略，
  支持只读核实和显式重新应用，不会因观察失败自动重启。
- 规则键为 FNV-1a 64 位哈希；极低概率哈希碰撞可能造成错误命中。当前未保留域名原文
  做二次碰撞校验。
- VPN、代理或隧道会把真实目的域名隐藏在另一层连接内；引擎只能观察隧道外层可见流量。

## 资源和失败策略

- 首次安装默认暂停，开机自启 `autostart` 独立配置默认关闭；旧配置缺项也不自启。
  开机脚本仅在明确开启自启、未手动暂停且 `sys.boot_completed=1` 后启动引擎；
  等待 180 次仍未完成则退出。关闭自启不停止当前引擎，手动启动也不打开自启。
- 单个下载最多 64 MiB；单次解压和多源累计解压最多 256 MiB、500 万行，单行缓存
  1024 字节。超限、HTML 错误页、损坏 gzip 和低有效率来源不会发布。
- NFQUEUE 用户态解析异常默认 ACCEPT；队列/verdict 故障触发看门狗移除路由规则，
  目标是优先恢复网络而不是保持拦截。
  仅忽略内核已移除包后，对精确匹配的有序 VERDICT 请求返回的 ENOENT，计入
  stale_verdicts；其它错误仍保护退出并保存 runtime=error 与 errno/sequence/请求类型。
  不对未知错误盲目重试，也不把真实故障显示成普通暂停。
- `--status` 的 `metrics` 字段和 `metrics.conf` 用于判断解析失败、截断、分片、命中、
  verdict/队列错误及重组资源淘汰，排障时应连同 engine 日志一起保存。
- 下载优先尝试可用的系统 libcurl，兜底执行固定路径 curl 或兼容所需安全选项的
  GNU wget。系统 libcurl/curl/wget 不是每台 Android 的 NDK 保证依赖；仅有 BusyBox
  wget 时可能没有可用的安全下载后端，失败会保留旧规则。BusyBox 缺少重定向限制，
  其内置 TLS 也不保证验证证书，不能以去掉安全选项的方式强行下载。
- 清理仅删除可由 `ADK_NFQ_` 链名确认归属的规则；不会按端口/队列编号删除其它
  模块的匿名 OUTPUT NFQUEUE/DROP。历史匿名布局需要由原版本显式迁移。

进一步的官方接口依据、故障注入和剩余验收项目见
[真机上线审计与验收方案](真机上线审计与验收方案.md)。
