# 指标与日志开销

本项属于待优化方案 O06，分阶段实施。当前先调整指标快照与空闲缓存维护，DNS 日志的有界异步批量写入尚待实施。没有宣称已经测得手机省电或延迟改善。

## 指标快照

守护 owner 每秒采样一次，数据变化才发布；相同内容每 15 秒发布一次心跳。`updated_at` 本身不算内容变化，最终退出可强制发布。失败不推进保存检查点，下次采样可重试；错误日志只在失败状态切换时记录。

`metrics.conf` 属于可丢失的观测快照，采用独占临时文件、完整写入及原子 rename，不再逐次 fsync。配置、规则指针、任务状态、生效回执和生命周期意图的持久化行为不受影响。断电可能丢失最新指标，不能拿它作为配置已生效或进程仍在运行的证明。

确定性时钟测试中，一个无流量小时的发布次数从旧策略 3601 次降为 241 次；这是策略测试的次数，并非真机写盘或耗电测量。活动计数仍在下一次一秒采样更新；心跳受 owner 调度影响，并非实时期限。会话归属与过期展示另归 O07。

## 空闲缓存

同一个 owner 周期维护 HTTP/TLS 和 TCP DNS 的未完成前缀，调用线程安全的 prune。没有新包也会按原有超时释放；统计查询仍为只读。原 `idle-retention` 缺陷探针已迁移至 `tests/test_idle_maintenance.cpp`，覆盖超时边界、时钟倒退及两类前缀释放；历史 audit 入口现在运行正确行为回归。

## 待验收

真机仍需对照日志开/关和高查询率下的 p50/p95/p99 延迟、CPU、RSS、写盘与队列丢包。Linux/主机测试不能替代厂商 Android 内核和文件系统的长稳数据。后续 DNS 缓冲须有明确容量、可观测丢弃数和退出策略，不能为了日志阻塞数据面 verdict。

## 第一阶段验证与暂停

严格主机全套、ASan/UBSan（含 75 项前端测试）、历史 audit 入口 sanitizer 和 Android API 31 严格编译通过。隔离 Debian arm64 的 nft/legacy 两套完整引擎集成通过，新增真实守护测试验证五秒空闲指标 inode/mtime 不变、活动数据及时发布，以及没有后续数据包的 HTTP 前缀到期回收；TCP DNS 同路径维护另有主机回归。没有连接或修改手机。

按用户要求在此阶段收尾提交后暂停，DNS 日志第二阶段留待恢复，尚不宣称 O06 全部完成。
