# 更新检查策略

本轮解决包含预览版时只看前三条 Release 导致漏检，以及完整发布正文超过 32 KiB 导致检查失败的问题。保留现有缓存、手动安装确认和渠道比较规则，不自动下载、安装或发布新版本。

## 查询范围

正式版优先读取 GitHub Latest 的 `update.json`，限制 32 KiB，校验模块 ID、版本、渠道、int32 版本序号、摘要和固定附件地址。网络或格式失败时，使用 `/releases/latest` 的正式版记录作后备。API 限流时，可用的静态更新信息仍能正常工作。

包含预览版时，使用 GitHub Release 列表，每页 5 条，最多 4 页。跳过草稿、无有效版本、附件缺失或身份不符的记录；遇到首个有有效候选的页面即停止，界面在该页候选中按版本号排序，同版本优先正式版。提前结束和页数上限降低匿名 API 请求消耗。扫描按 GitHub 返回的发布顺序进行，不声称对整个仓库历史做了全局版本排序。

不足一页即视为列表结束；20 条均无有效候选时明确报错。分页中途限流、超时、损坏或不完整响应，也作为本次失败，不显示“已是最新”，不缓存未确认的检查结果。没有跟随响应里任意的 `next` URL，只生成固定 API 地址的页码参数。参数依据 [GitHub Release 列表文档](https://docs.github.com/en/rest/releases/releases#list-releases)。

检查渠道和安装渠道继续分开核验：包含预览版可以发现两种渠道；正式版用户不降级到同数字版本预览版，已识别的预览版允许升级同数字版本正式版。版本解析与原生安装准入共用同一份 C++ 实现，前端保留对应行为回归。

## 总预算与完整响应

一次检查共用 25 秒、2 MiB 正文预算；单个 API 响应最多 512 KiB。静态元数据失败后再访问 API 也不重新计时。这里只增加更新文档入口，规则片段预览仍保持原有 32 KiB 上限。

更新文档必须是完整 HTTP 200 响应，不发送 Range，不接受 206 或达到大小限制后截取的前缀。不会把恰好以合法 JSON 结尾的 HTTP 片段当成完整列表。保持已有 HTTPS 证书核验、重定向限制和固定 argv；不跨下载后端重复失败请求。

库初始化与同步 DNS 解析可能不及时响应 curl 超时，所以新入口在核实单线程且库尚未初始化的 CLI 中，将库工作交给受父进程监督的子进程；父进程执行总期限和有界管道回收，Linux 下父进程死亡会终止该库子进程。库不可用或不能安全 fork 时选择独立 curl，查询失败不再换后端重试。未确认退出会阻止后续请求。子进程收尾另受现有 200 毫秒回收预算约束。

正文只在内存和有界管道中传递，不写临时响应文件，不创建模块正式数据目录。预算以接受的正文计数，不等于 TLS、响应头和重定向的网络总流量。

## 返回结果与日志

检查更新只返回版本、渠道、发布地址和两个必要附件的名称、大小、地址。舍弃正文、作者、下载次数等无关 API 元数据，保证普通结果可被现有缓存保存。ZIP 为 4 字节至 64 MiB，校验和附件为 1–512 字节；相关附件必须唯一，地址必须与版本和本项目仓库完全对应。下载后仍校验 SHA-256、模块身份、版本序号和渠道。

更新日志单独读取最新一条 Release，包含预览版，不需要安装附件，也不退回本地历史。只返回标题、日期和正文；正文最多 16,000 UTF-8 字节，保留完整码点，截取时标记 `body_truncated`，界面提示可在 GitHub 查看完整内容。外部内容仍作为文本显示。成功记录沿用 24 小时日志缓存，检查结果沿用 6 小时缓存和安装版本/渠道上下文；从缓存发起下载仍先重新检查。

解析器限制原始 JSON 512 KiB、25,000 个值、32 层嵌套。拒绝重复字段、不完整语法、非法 UTF-8、孤立代理项及不符合整数格式的大小/版本序号；不把解析失败、未知身份或查询上限转换成空的成功结果。

## 验证入口

- `STRICT=1 make test` / `make test-sanitize`：严格 JSON 语法、Unicode、重复字段、深度/容量、字段精简、附件唯一性、分页停止、限流与共享预算，原有版本/渠道、缓存和前端交互逻辑。
- `make test-download-integration`：新增完整文档用例，实际运行 libcurl 和 curl；覆盖大于 32 KiB、恰好达到上限、超出上限、206、禁止 Range、尾部延迟、多请求共享时间/字节，以及初始化阻塞后的真实子进程回收。原有规则下载、HTTP 验证器和片段预览同时回归。
- `make test-update-integration`：实际模块 CLI 遇到第一页面 5 个无附件版本后找到第二页候选，长中文日志精简、分页损坏/限流/截止、静态信息后备，以及原有下载校验、预览转正式与管理器安装桩回归。只在一次性 Linux/root 环境运行。
- `make fuzz-smoke`：新增发布 JSON 目标和有效/非法种子；无 libFuzzer 时沿用确定性 ASan/UBSan 驱动，不能当作长时 fuzz 验收。O13 的持续 corpus 和更广状态测试仍待做。
- Playwright：手机/折叠屏/平板、长日志提示、同版本预览转正式、更新提示和日志缓存重新打开。

这些检查不等于 Android 网络和厂商管理器的真机验收。本轮不安装手机模块、不操作系统网络，也不发布新版本。
