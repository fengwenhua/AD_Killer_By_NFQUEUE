# AD_Killer_By_NFQUEUE 真机上线审计与验收方案

日常只读排查和卸载后的独立残留检查，请先参阅 [ADB 状态检查与卸载残留排查](ADB状态检查与卸载残留排查.md)。

## 1. 审计结论

当前实现已把 NFQUEUE 线协议、ACK、fail-open、conntrack 标记、TCP TLS/HTTP 重组、
TCP DNS 重组、iptables 事务、进程生命周期和 CI 的主要可验证风险纳入自动化门禁。
主机单元测试或 GitHub Linux runner 无法证明所有 Android vendor 内核、root 管理器与
iptables 后端均无缺陷，因此发布结论应写成“通过指定矩阵验收”，不能写成“保证真机
零 bug”。

## 2. 官方协议依据

| 实现点 | 采用的协议约束 | 官方依据 |
|---|---|---|
| verdict | `nfqnl_msg_verdict_hdr` 按 `verdict`、`id` 两个网络序 32 位字段编码 | [Linux NFQUEUE UAPI](https://github.com/torvalds/linux/blob/master/include/uapi/linux/netfilter/nfnetlink_queue.h) |
| copy 参数 | `nfqnl_msg_config_params` 为网络序 `copy_range` 加 8 位 `copy_mode` | [Android Bionic UAPI](https://android.googlesource.com/platform/bionic/%2B/9d4a56e490024868d5cad890b79f1ebdb1a66ed4/libc/kernel/uapi/linux/netfilter/nfnetlink_queue.h) |
| fail-open | `NFQA_CFG_F_FAIL_OPEN` 处理队列满或无法向用户态投递；`--queue-bypass` 只处理无监听器 | [Linux 内核实现](https://github.com/torvalds/linux/blob/master/net/netfilter/nfnetlink_queue.c) |
| connmark verdict | `NFQA_CT` 嵌套 conntrack 属性；`CTA_MARK_MASK` 只更新掩码范围 | [libnetfilter_queue 官方示例](https://www.netfilter.org/projects/libnetfilter_queue/doxygen/html/nf-queue_8c_source.html)、[Linux conntrack 实现](https://github.com/torvalds/linux/blob/master/net/netfilter/nf_conntrack_netlink.c) |
| 消息构造 | verdict、packet id、嵌套属性的方向与官方 helper 一致 | [libnetfilter_queue nlmsg 实现](https://git.netfilter.org/libnetfilter_queue/tree/src/nlmsg.c) |

生产代码直接包含 Linux/Android NDK UAPI 头，不再维护容易漂移的私有常量副本。

## 3. 已纳入自动化门禁的风险

- Netlink：ACK sequence、kernel sender pid、错误 ACK、`NLMSG_OVERRUN`、错误版本、
  重复属性、非法 `CAP_LEN`、截断 datagram 和 packet queue id。
- Verdict：packet id 网络序、普通 ACCEPT/DROP、带掩码 PASS/BLOCK connmark。
- 路由：IPv4/IPv6 完整代际、稳定入口链、scope、UID 规则、DNS/TLS queue、QUIC、
  connmark DROP/RETURN 顺序和旧 connbytes 规则拒绝。
- 解析：IPv4/IPv6、扩展头、DNS UDP/TCP、多问题与压缩指针、TCP DNS 分段/乱序/
  重传/多帧、TLS 多 record、HTTP 完整 Host 行、资源上限与超时。
- 生命周期：启动信号竞态、持久暂停、安装存储失败、UID 缓存失败、重复卸载清理、
  模块脚本语法与静态检查。
- 工程：严格告警、ASan/UBSan、解析 fuzz、Android NDK arm64 构建、可复现 ZIP、
  包结构和 checksum。

## 4. CI 发布门禁

所有项目必须成功，任一失败不得发布：

1. `STRICT=1 make test`：所有主机单元与契约测试。
2. `make test-sanitize`：ASan/UBSan 全套测试。
3. `FUZZ_CXX=clang++ FUZZ_RUNS=1000 make fuzz-smoke`：packet/rule/netlink 解析烟测。
4. `make test-nfqueue-integration`：真实 Linux 内核双栈 queue、payload、verdict、
   fail-open、PASS/BLOCK connmark。
5. `bash -n`、`sh -n` 和 ShellCheck：构建、安装、服务、卸载及测试脚本。
6. NDK r26 arm64 严格构建两次，ZIP SHA-256 相同；随后验证模块结构和 checksum。
7. `make test-download-integration`：实际 libcurl/curl HTTP/TLS、重定向和文件失败保护。
8. `make test-engine-integration`：一次性 Linux/root 下完整引擎双栈 DNS/HTTP/TLS、
   scope 切换、CLI 停止、强杀后的 bypass/重启、connmark 冲突拒绝及外部规则保留。

## 5. 真机测试矩阵

最低建议矩阵：

| 维度 | 必测组合 |
|---|---|
| Android | 12/API 31、当前主流版本、最新可用版本 |
| Root | KernelSU、APatch、Magisk 各至少一台 |
| 内核 | GKI 与至少一个厂商定制内核 |
| iptables | legacy 与 nft wrapper（设备支持时） |
| 网络 | Wi-Fi、蜂窝、IPv4-only、IPv6/双栈、VPN 开/关 |

每台设备记录：型号、ROM build、内核版本、root 管理器版本、`iptables --version`、
是否具备 NFQUEUE/fail-open/conntrack mark，以及模块 ZIP checksum。

## 6. 真机功能与故障注入

### 必测功能

1. UDP/TCP DNS 的允许与阻断；TCP 查询使用小 MSS 或代理制造跨 segment、乱序和重传。
2. HTTP Host 与 TLS ClientHello SNI 的允许与阻断；覆盖 IPv4/IPv6、多 TLS record、
   大 ClientHello，以及超过 12 个重传后仍不能绕过。
3. PASS 连接判定后不再重复进入 queue，BLOCK 连接后续包持续丢弃；确认 connmark
   本模块掩码以外的 26 位（含系统低 20 位和 bit 24/25）保持不变。
4. scope 0/1、应用名单、白名单、QUIC 开关、规则热重载和规则源更新。
5. WebUI 启停、暂停后重启仍暂停、显式启动恢复、卸载后双栈网络立即可用。

### 必测故障

1. 在规则加载、queue 建立、iptables 切换各阶段发送 SIGTERM；不得残留活动链。
2. `kill -9` daemon 后执行 status/stop/下次开机；残留规则必须可清理，网络可恢复。
3. 人为占用 queue 0/1、禁用相关内核模块或让 connmark 规则失败；启动必须失败且不得
   挂载半套规则。
4. 制造 queue 压力和用户态短暂停顿；验证 fail-open、队列错误指标与看门狗拔链。
5. IPv6 规则创建或代际切换中途失败；IPv4/IPv6 必须一起回滚到旧代际。
6. 数据目录只读、磁盘满、配置损坏、下载中断、gzip 损坏；旧规则和网络状态不受损。

## 7. 性能与稳定性门槛

- 连续运行 24 小时，无 daemon 重启、规则残留、持续队列错误或不可解释 RSS 增长。
- 默认完整规则集下记录启动时间、热重载时间、峰值 RSS、CPU、queue drop 和请求延迟。
- 压力测试后 `reassembly_bytes` 回落，flow 数不超过配置上限，日志和任务目录保持上限。
- 与模块关闭时相比，常用网页与应用的连接建立延迟应在项目预先约定的预算内；预算
  必须以目标低端设备数据确定，不能用 CI runner 数据代替。

## 8. 发布与回滚

发布必须附带：commit、模块版本、ZIP SHA-256、CI 链接、真机矩阵记录、已知限制和
回滚包。若出现断网、启动残留规则、错误阻断系统流量、daemon 循环崩溃或 connmark
冲突，立即停止发布并执行 `AD_Killer_By_NFQUEUE --stop`；二进制不可用时运行卸载脚本的手动清理
路径，确认 `iptables -t mangle -S` 与 `ip6tables -t mangle -S` 不再包含 `ADK_NFQ_`。

ECH、DoH/DoT、DNSCrypt、VPN/代理内层域名、真实 IP 分片和未覆盖端口属于已声明协议
边界，不应以扩大抓包范围或静默误判方式“修复”；若要支持，应单独设计协议和隐私模型。
