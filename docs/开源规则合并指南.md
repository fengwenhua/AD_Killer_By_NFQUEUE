# 开源规则合并：C++ 原生配方与 Python 比对

## 普通配方、Hosts 并集与内置来源

普通配方文件为 [`src/rule_recipe.inc`](../src/rule_recipe.inc)，C++ 编译时直接使用，
Python 参考脚本读取同一个文件，避免维护两套 URL。当前为 **20 个普通来源**，分三类：

- **AdGuard 语法（15 个）**：AdGuard DNS、AdGuard Mobile Ads、AdGuard Tracking Protection、
  EasyList、EasyList China、EasyPrivacy、oisd small、CJX、乘风视频过滤规则、anti-AD、
  AWAvenue、HaGeZi Light、AdRules DNS List、hostsVN Threat、轻量广告拦截规则（banad）。
- **Hosts 转精确域名（1 个）**：hostsVN。按显式 Hosts 输入转换为 AdGuard 精确域名，
  不是按文件名猜测。
- **原生 Hosts 并集（4 个）**：anti-AD domains、oisd big、1Hosts Lite、StevenBlack hosts。
  这些来源按 Hosts 语法归一化后写入 `hosts_rules.gz`，供“仅 Hosts”模式使用。

另有一个 **HaGeZi 内置来源**：新安装默认完整 Pro，旧安装保留原 Pro − Fake 配方及启停。
可在卡片中选择配方，保存并同步后生效。固定地址位于 `src/builtin_sources.h`，不能编辑
地址或删除内置项。它不在普通来源 Python/快照配方内，两种配方通过同一输入的独立 Python 集合验证，
详见[特殊来源说明](HaGeZi内置特殊来源.md)。

所有规则规范化后按分类排序、去重：普通 AdGuard 来源与 hostsVN 输出 `adguard_rules.gz`；
四个原生 Hosts 来源输出 `hosts_rules.gz`。启用内置来源时，所选 Pro 或 Pro − Fake 结果额外写入
Hosts 分类。因此“仅 Hosts”模式现在加载的是多源 Hosts 并集，而不是仅一份列表。

**使用默认完整配方应选择“Hosts + AdGuard”。** “仅 Hosts”模式不加载 AdGuard 文件，
但仍包含上述四个 Hosts 来源与所选内置 HaGeZi 配方，并可使用自定义规则。未知的用户自定义
URL 保留原有 AUTO 分类策略（先尝试 Hosts 语法 → Hosts 分类，否则 AdGuard → AdGuard 分类）。

首次安装写入 20 个普通来源和启用的完整 Pro，标记 `source_defaults_version=3`。
从 v2 升级不改写现有来源文件或配方，只更新完成标记。更早的来源迁移会：移除已失效的
`https://adrules.top/adrules.txt`；把乘风
`rule.txt` 换成视频列表 `mv.txt`；追加 HaGeZi Light、AdRules DNS、hostsVN Threat、
banad 与四个 Hosts 列表（已存在则保持原启停状态）。旧地址的停用状态继续保留，
已配置新地址时以新地址为准，不生成重复项；追加遵守 64 个普通来源和 256 KiB 上限。
自定义列表中的内置 HaGeZi 保留原配方和启停状态，缺失时补为停用的旧配方；未修改的
历史默认模板更新普通来源，但保留 HaGeZi 配方和启停。后续手动修改及更高版本迁移标记不会被覆盖。
安装与同步/来源编辑互斥；不改变暂停或自启配置，也不自动发布规则。

HaGeZi Light 暂保留：当前内置 Pro 将 wildcard 归一化为精确 Hosts，Light 使用 AdGuard
后缀规则。上游包含关系不等于本模块中的匹配等价，不能只按域名数量直接删除 Light。
具体快照评估和覆盖边界见[特殊来源说明](HaGeZi内置特殊来源.md)。

## 解析和失败策略

- 保留裸域名、`||domain^`、`*.domain`、`@@` 例外；精确/后缀、黑/白分开去重。
- 路径、正则、cosmetic/scriptlet、请求级修饰符、非法域名前缀等不扩大为域名拦截。
- 域名至多 253 字节，每标签至多 63 字节。Hosts 输入可归一化单个根点，但
  AdGuard 的末尾点是未支持的域名前缀模式，不能通过删点转换成完整域名。
- 显式 AdGuard 浏览器列表可能大部分是 cosmetic/请求规则，允许提取其中非空的
  域名子集，不套用 AUTO 的 5% 有效率门槛。HTML、空输入、坏 gzip、字节/行数/
  单行上限仍拒绝；AUTO 的低有效率保护保持不变。
- 手机同步要求所有启用来源有校验通过的内容；失败时只可复用 24 小时内核验的来源缓存，
  否则中止并保留整份旧 generation，不发布成功子集。
- 手机有独立校验缓存，可用条件请求确认未变化，与 Python 的电脑缓存无关；不会关闭 TLS
  证书验证。预算、缓存年龄与整组回退详见[规则同步策略](规则同步策略.md)。

## 手机正常使用

安装后保持守护暂停、不开机自启，先在“规则 → 开源规则来源”确认列表与启用状态，
可单独测试来源，再回概览同步。同步只更新规则；不会主动启动已暂停的引擎。
运行中同步沿用现有热重载行为。

除定向默认迁移外，用户编辑过的来源会原样保留；若不是默认配方，需要自行调整后保存再同步，
不能把不同配方、不同上游版本或不同成功来源集合的数量直接当作一致性验收。

新版使用 `rules.current` 指向不可变 generation。不要手工覆盖根目录 gzip 并假设
立即生效，也不要为了导入而删除指针或绕过原子发布。

## 电脑参考脚本与固定快照

Python 仅需标准库。默认使用以 URL SHA-256 命名的电脑缓存；缓存不会自动过期，
联网复算时应使用 `--fresh`。证书失败应修复 CA 路径，不允许以关闭验证来“修复”。
本机 python.org 安装缺少默认 CA 时可显式指定可信 CA 文件，例如
`SSL_CERT_FILE=/etc/ssl/cert.pem`；不要把该路径当成其他系统的通用路径。

```bash
# 同时冻结原始文件、来源顺序/格式、下载错误和输入 SHA-256。
# 快照目录必须不存在；输出目录由调用者选择。
python3 scripts/merge_rules.py --fresh \
  --snapshot-dir dist/recipe-snapshot --out-dir dist/python-result

# 完全离线重放相同输入，不再访问上游。
python3 scripts/merge_rules.py --from-snapshot dist/recipe-snapshot \
  --out-dir dist/python-replay

# 在可运行该二进制的平台执行（Android arm64 包不能在 macOS 直接运行）。
# C++ 离线命令不需要 root，输出目录必须尚不存在。
AD_Killer_By_NFQUEUE --merge-snapshot dist/recipe-snapshot dist/native-result

# 比较完整规则集合、两侧独有项、精确字节 SHA-256 和黑白数量。
python3 scripts/compare_rule_results.py dist/python-result dist/native-result \
  --report dist/parity.json
```

快照目录包含 `sources.tsv`、成功下载的编号文件和 `receipts.json`；格式列取
`adguard`、`hosts-as-adguard`、`hosts` 或 `auto`。失败下载用 `-` 记录，
HTTP 200 HTML 保留原始文件再由两侧分别拒绝，不能为“对齐”偷偷换源或删记录。
原始文件可能是 gzip，扩展名不决定解析方式。

原生 `--merge-snapshot` 只写调用者指定的新输出目录，输出两类文本/gzip、引擎实际
复算的 `rule_stats.conf`、逐源 `source_stats.conf` 和隔离日志。不触碰运行数据、
防火墙、规则指针、配置或守护进程。它用于隔离比对，不是安装/发布命令。

## 验证建议

使用同一快照分别运行 Python 参考实现与 C++ `--merge-snapshot`，再通过
`compare_rule_results.py` 比较完整集合、黑白规则数量和规范化文件 SHA-256。
数量会随上游更新与当次可用来源变化，不能把文档中的历史计数当作固定目标。

发布前应完成严格主机测试、ASan/UBSan、真实 CLI 更新/安装互斥测试、Android
arm64 PIE 与 16 KiB ELF 校验、ZIP 结构校验和双次可复现构建。手机首次验收时保持
暂停与不开机自启，先检查来源报告并同步，再单独测试手动启动和停止。
