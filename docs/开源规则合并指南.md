# 开源规则合并：C++ 原生配方与 Python 比对

## 普通配方与可选内置来源

普通配方不包含 HaGeZi，单一配方文件为 [`src/rule_recipe.inc`](../src/rule_recipe.inc)，C++ 编译时直接使用，
Python 参考脚本读取同一个文件，避免维护两套 URL。
另有默认启用的 HaGeZi Pro − Fake 内置特殊来源，可在 WebUI 停用，保存后同步。
该内置来源的固定地址位于 `src/builtin_sources.h`；不能编辑/删除，可整组测试和启停。
它不在普通来源 Python/快照配方内，差集通过同一输入的独立 Python 集合验证，
详见[特殊来源说明](HaGeZi内置特殊来源.md)。

12 个普通来源：AdGuard DNS、AdGuard Mobile Ads、AdGuard Tracking Protection、
EasyList、EasyList China、EasyPrivacy、oisd small、CJX、乘风、anti-AD、
AWAvenue、hostsVN。具体地址和输入格式以配方文件为准。

前 11 个按 AdGuard 域名子集解析；hostsVN 按显式 Hosts 输入转换为 AdGuard 精确
域名。它与旧脚本分类相同，不是按文件名猜测。所有规则规范化后排序、去重，输出
`adguard_rules.gz`；未启用特殊来源时，`hosts_rules.gz` 仅含注释头，没有开源规则。

**使用默认完整配方应选择“Hosts + AdGuard”。** “仅 Hosts”模式不加载该 AdGuard
文件，但仍可使用其支持的自定义规则。未知的用户自定义 URL 保留原有 AUTO 分类策略。

首次安装写入 12 个普通来源和启用的 HaGeZi 内置项，已从默认配方移除 AdRules DNS List。升级时仅首次定向删除该 AdRules URL 并启用 HaGeZi；其他自定义来源、注释和停用状态保留。成功后记录 `source_defaults_version=1`，之后手动停用 HaGeZi 会被保留。未修改的历史默认模板直接切换到新配方。安装与同步/来源编辑互斥；不改变暂停或自启配置，也不自动发布规则。

## 解析和失败策略

- 保留裸域名、`||domain^`、`*.domain`、`@@` 例外；精确/后缀、黑/白分开去重。
- 路径、正则、cosmetic/scriptlet、请求级修饰符、非法域名前缀等不扩大为域名拦截。
- 域名至多 253 字节，每标签至多 63 字节。Hosts 输入可归一化单个根点，但
  AdGuard 的末尾点是未支持的域名前缀模式，不能通过删点转换成完整域名。
- 显式 AdGuard 浏览器列表可能大部分是 cosmetic/请求规则，允许提取其中非空的
  域名子集，不套用 AUTO 的 5% 有效率门槛。HTML、空输入、坏 gzip、字节/行数/
  单行上限仍拒绝；AUTO 的低有效率保护保持不变。
- 手机同步要求所有启用来源有校验通过的内容；失败时只可复用 24 小时内核验的来源缓存，否则中止并保留整份旧 generation，不发布成功子集。
- 手机有独立校验缓存，可用条件请求确认未变化，与 Python 的电脑缓存无关；不会关闭 TLS 证书验证。预算、缓存年龄与整组回退详见[规则同步策略](规则同步策略.md)。

## 手机正常使用

安装后保持守护暂停、不开机自启，先在“规则 → 开源规则来源”确认列表与启用状态，
可单独测试来源，再回概览同步。同步只更新规则；不会主动启动已暂停的引擎。
运行中同步沿用现有热重载行为。

除上述一次性定向迁移外，用户编辑过的来源会原样保留；若不是默认配方，需要自行调整后保存再同步，不能
把不同配方、不同上游版本或不同成功来源集合的数量直接当作一致性验收。

新版使用 `rules.current` 指向不可变 generation。不要手工覆盖根目录 gzip 并假设
立即生效，也不要为了导入而删除指针或绕过原子发布。

## 电脑参考脚本与固定快照

Python 仅需标准库。默认使用以 URL SHA-256 命名的电脑缓存；缓存不会自动过期，
联网复算时应使用 `--fresh`。证书失败应修复 CA 路径，不允许以关闭验证来“修复”。
本机 python.org 安装缺少默认 CA 时可显式指定可信 CA 文件，例如
`SSL_CERT_FILE=/etc/ssl/cert.pem`；不要把该路径当成其他系统的通用路径。

```bash
# 同时冻结原始文件、来源顺序/格式、下载错误和输入 SHA-256。
# 快照目录必须不存在；输出目录由调用者选择。
python3 scripts/merge_rules.py --fresh \
  --snapshot-dir dist/recipe-snapshot --out-dir dist/python-result

# 完全离线重放相同输入，不再访问上游。
python3 scripts/merge_rules.py --from-snapshot dist/recipe-snapshot \
  --out-dir dist/python-replay

# 在可运行该二进制的平台执行（Android arm64 包不能在 macOS 直接运行）。
# C++ 离线命令不需要 root，输出目录必须尚不存在。
AD_Killer_By_NFQUEUE --merge-snapshot dist/recipe-snapshot dist/native-result

# 比较完整规则集合、两侧独有项、精确字节 SHA-256 和黑白数量。
python3 scripts/compare_rule_results.py dist/python-result dist/native-result \
  --report dist/parity.json
```

快照目录包含 `sources.tsv`、成功下载的编号文件和 `receipts.json`。失败下载用 `-`
记录，HTTP 200 HTML 保留原始文件再由两侧分别拒绝，不能为“对齐”偷偷换源或删记录。
原始文件可能是 gzip，扩展名不决定解析方式。

原生 `--merge-snapshot` 只写调用者指定的新输出目录，输出两类文本/gzip、引擎实际
复算的 `rule_stats.conf`、逐源 `source_stats.conf` 和隔离日志。不触碰运行数据、
防火墙、规则指针、配置或守护进程。它用于隔离比对，不是安装/发布命令。

## 验证建议

使用同一快照分别运行 Python 参考实现与 C++ `--merge-snapshot`，再通过
`compare_rule_results.py` 比较完整集合、黑白规则数量和规范化文件 SHA-256。
数量会随上游更新与当次可用来源变化，不能把文档中的历史计数当作固定目标。

发布前应完成严格主机测试、ASan/UBSan、真实 CLI 更新/安装互斥测试、Android
arm64 PIE 与 16 KiB ELF 校验、ZIP 结构校验和双次可复现构建。手机首次验收时保持
暂停与不开机自启，先检查来源报告并同步，再单独测试手动启动和停止。
