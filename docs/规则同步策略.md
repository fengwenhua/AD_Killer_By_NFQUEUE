# 规则同步策略

本节记录已经生效的同步约束。规则同步和单源测试使用同一下载与校验路径；单源测试不发布规则、不修改正式来源统计、不启动引擎。

## 预算与取消

| 范围 | 默认限制 |
| --- | --- |
| 整次同步 | 单调时间 10 分钟 |
| 单个来源 | 90 秒，且不超过整次剩余时间 |
| HaGeZi Pro − Fake | 两个依赖合计共享一个来源的 90 秒 |
| 单个响应正文 | 64 MiB |
| 整次接收的正文预算 | 256 MiB；HaGeZi 每组最多 128 MiB |
| 累计解压与解析 | 256 MiB、500 万行，拒绝的内容也占用预算 |

这些是任务的资源限制，不是进程 RSS 或耗电保证。网络正文不含 TLS、响应头和内核缓冲等传输开销；没有完整字节回报的失败/被杀下载保守占用整份预留额度，而非将其当作零流量。curl 用父进程有界采集的传输回报结算，GNU wget 只在成功退出且文件大小核实时返还额度。来源解析失败后再校验缓存，也计入同一份累计解压/行数预算。

下载父进程监督自己创建、尚未回收的子进程/进程组，因此库初始化、同步 DNS 解析卡住也不依赖 libcurl 回调才能取消。只有可核实的单线程 CLI、且父进程尚未初始化库时才在 fork 子进程中运行 libcurl；否则在请求前选择固定路径的 exec 后端。子进程继承任务与模块操作租约，结束未确认时保留临时文件并拒绝后续下载。Linux 库下载子进程随所有者死亡而取消，不能在父进程崩溃后继续无限等待库内初始化。

网络监督以约 20 毫秒轮询，结束核验另有至多 200 毫秒的等待窗口。解压以固定块检查取消；整理、压缩、staging 和发布前检查任务预算。CPU 排序、文件系统调用或不可中断的内核 I/O 不是可抢占的实时任务，不能声称任意故障下整个 CLI 都严格在第 600 秒退出。无法确认结束的写入者仍会阻止卸载删除数据。

正式同步将剩余来源时间的约 20% 留给本地校验/缓存回退，网络阶段最多 70 秒。多个依赖和有限重试共享该阶段。单源测试不读取缓存，仍受完整的单源/任务预算约束。

原始下载放在独立的 `source_staging/job-*`，目录租约由实际写入者跨 exec 继承。正常结束后删除；崩溃残留由下次同步在取得独立独占租约后回收，不根据目录里的 PID 猜测进程是否活着。最多容纳两个仍被写入者占用的暂存区，达到上限拒绝新下载。只清理预期普通文件，目录枚举有界；未知对象、链接或内部挂载点不递归清理。缓存和暂存均检查同设备 bind mount，避免把外部目录误作本模块临时文件。

## 失败与发布

一次请求失败后不通过另一个后端重复请求；GNU wget 固定一次尝试。库不存在时可以选择 curl，curl 不存在时可以尝试兼容的 GNU wget；证书、协议、重定向和内容限制继续强制执行。规则任务中，连接失败、传输中断和 HTTP 502/503/504 可在剩余预算允许时等待约 200 毫秒并最多再试一次；证书、普通 HTTP 错误、429、内容校验失败和预算耗尽不重试。

所有已启用来源必须有本次校验通过的内容，才允许生成并发布新规则。来源无法下载且没有合格缓存时立即停止后续请求，返回失败并保留整份旧规则；统计中标明尚未请求的来源。用户可以明确关闭故障来源后再同步。HaGeZi 必须完整取得并校验 Pro 与 Fake 后才做本组差集，不将未完成的 Pro 泄漏进结果，也不影响其他来源。

## 条件请求与来源缓存

缓存位于私有 `source_cache`。身份键包含来源、格式、配方版本和全部依赖 URL；每个正文有 SHA-256、大小与获取时间，组记录有最后完整核验时间。使用前核对普通文件、权限、单链接、摘要、来源身份和时钟，不跟随符号链接。内容仍走与新下载相同的解析器，不只信任旧的条数或摘要；解析后再次核对摘要，拒绝等待 304 期间或解析前后发生的持久损坏。新下载也先捕获摘要，缓存复制必须与校验过的摘要一致。

libcurl/curl 支持 ETag 优先、Last-Modified 备用的条件请求，累计响应头最多 16 KiB。验证器拒绝控制字符与通配 ETag；跳转、临时响应与 trailer 不覆盖最终响应的验证器。304 只有在已经核实对应缓存时才可复用，并要求最终 URL 与缓存记录一致；地址变化则在原预算内进行一次不带条件的完整下载。没有缓存的 304 直接失败。GNU wget 兼容路径始终完整下载，仍可使用相同的校验后缓存回退。

| 使用结果 | 行为 |
| --- | --- |
| 新正文校验通过 | 可以提交该来源缓存 |
| 条件请求确认未变化 | 校验原缓存后更新核验时间；全部依赖均为 304 时只替换组元数据，不复制正文 |
| 下载/新内容失败 | 只允许使用最后完整核验距今不超过 24 小时的缓存；不会刷新旧核验时间 |
| 旧缓存超过 24 小时 | 不允许失败回退；7 天以内仍可经服务器有效 304 重新核验 |
| 超过 7 天、未来时间或内容损坏 | 不发送旧验证器，重新完整下载；失败保留整份旧规则 |

HaGeZi 的新 Pro + 新 Fake，或本次成功核验的 304 组件，可组成一个本次完整组。任一依赖失败或内容不合格时，只能回退整份旧组，不能混用新 Pro 和旧 Fake。只有整组解析通过后才提交缓存。单源测试只使用新请求，不读取、刷新或提交正式缓存。

缓存采用不可见 staging、正文/元数据同步、单个组指针原子切换。提交前失败保留旧组；指针已可见但目录同步失败时明确记为持久化未确认，不错误保证仍是旧指针。下次回收先同步目录，再清理不再被指针引用的代际。不会在缓存异常时清空规则或跳过剩余的完整来源保护。

稳定缓存目标为原始正文合计 256 MiB、65 个来源；当前启用来源受保护，容量不足可回收停用的旧条目，保护项/未知对象阻止回收时停止新增缓存并记录。原子替换期间最多额外保存一组正文（最多 128 MiB），metadata 另有固定大小与枚举上限；写入前要求保留至少 16 MiB 空间。临时目录或文件系统故障下不能把目标配额宣称为整个数据目录的绝对硬限制。升级保留缓存，完整卸载随其他模块数据删除。

来源卡片区分“同步成功”“服务器确认 304”和“已同步（使用缓存）”，最后一种以警示色显示同步时的缓存年龄及失败原因。同步总结也提示复用缓存的来源数。旧版本曾发布过部分来源的历史统计仍能读取；当前失败的完整性检查不会显示为“已合并成功来源”。发布结果不明确时不保证仍是旧规则。

HTTP 行为依据 [RFC 9110 条件请求](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-none-match) 与 [libcurl 响应头回调](https://curl.se/libcurl/c/CURLOPT_HEADERFUNCTION.html)；请求头按 [CURLOPT_HTTPHEADER](https://curl.se/libcurl/c/CURLOPT_HTTPHEADER.html) 的要求显式过滤，不能假定库会替调用方清理控制字符。

## 已执行的验证

- 真实 libcurl/exec curl 多慢源共用任务期限、独立来源期限、累计正文上限、失败保留旧文件、已确认退出的临时文件清理。
- 人工卡住 libcurl 初始化，确认父监督在库自己的超时配置之前也能结束下载；Linux 上强杀测试所有者，确认继承租约最终释放。
- 隔离 Linux 真实 CLI 连续慢源：停止后续请求，不产生 staging、不改变旧代际，下次新任务不继承旧期限。
- 完整来源发布回归：普通来源失败和 HaGeZi 任一依赖失败，即使其他来源成功也不发布半份规则。
- 条件请求覆盖真实 libcurl/curl 的 ETag/Last-Modified、最终跳转地址、304、重复验证器/控制字符/超大响应头与有限瞬时重试。
- 持久缓存覆盖真实 CLI 的 304 复用、过期/时钟回退、损坏后完整重取、地址变化、无缓存 304 拒绝、慢请求后回退、HaGeZi 失败整组回退、测试不读写缓存和 owner 崩溃重进；挂载/链接保护、配额与提交故障也有正式回归。

Android 严格编译和 Linux 测试不替代手机网络环境、厂商内核与掉电验收。
