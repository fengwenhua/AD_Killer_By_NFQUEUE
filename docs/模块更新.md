# 模块更新

v1.2 在“设置 → 检查更新”提供独立更新页面。v1.1 用户可通过在线更新升级；首次从 v1.0 升级时，在根管理器中手动安装完整 ZIP。

1. 点击“检查更新”，默认读取本仓库最新正式版附带的静态 `update.json`，不占用 GitHub API 配额；缺少元数据时回退查询 API。勾选“包含预览版”后，通过 API 从最近 3 个 Release 中选择有效的最高数字版本。
2. 点击“下载并校验”，后台获取对应标签下的 ZIP 与 `.sha256`。固定仓库和文件名、HTTPS、最多 64 MiB、SHA-256 及 ZIP 文件头检查均通过后才允许安装。
3. 点击“安装”并确认，通过 `/data/adb/ksud module install`、`/data/adb/apd module install` 或 `/data/adb/magisk/magisk --install-module` 调用设备根管理器。多个管理器并存或找不到接口时，请通过发布页下载 ZIP 并在管理器手动安装。
4. 成功后手动重启。当前运行版本会保留到重启；不自动重启。

后台任务复用 `--update-status JOB_ID` 协议，保留有界日志。关闭 WebUI 不终止任务；同一管理器重新打开时可恢复查询。已下载包位于私有目录 `/data/adb/AD_Killer_By_NFQUEUE/module_updates/package.zip`，安装前重新计算 SHA-256。网络失败、校验失败或未知任务状态均不会显示安装成功。

“自动检查更新”默认关闭；启用后，每次打开 WebUI 检查一次，开启开关时也会检查。自动检查与“包含预览版”设置保存在当前 WebUI 的本地存储中，不影响其他管理器；存储受限时仅当前会话有效。无论是否启用自动检查，下载和安装都需要用户操作，不会自动安装或重启。

更新日志通过 `--module-release-notes` 读取 GitHub 最新一条公开 Release，包含预览版。成功结果在当前管理器的 WebUI 本地存储缓存 24 小时，重开界面优先使用缓存；可点击“重新加载”立即刷新。刷新失败时标明仍显示上次读取的记录，不用项目内置日志冒充远端内容。远端文本按纯文本显示，不执行 HTML。

检查更新的成功结果按正式／包含预览渠道分开缓存 6 小时，绑定当前安装版本、构建序号及渠道。关闭重开后，设置列表仍可显示“有更新”；缓存过期、安装版本变化、渠道不匹配或数据损坏时不复用。缓存恢复不会自动安装，点击下载前会重新检查发布信息。存储被拒绝或清空时退回当前会话，不阻塞更新功能。

这些缓存不与 KernelSU 等管理器的原生更新图标同步；管理器通过标准 `updateJson` 独立检查正式版，使用与验收见[KernelSU 原生更新](KernelSU原生更新.md)，协议调研见[根管理器原生更新提示调研](根管理器原生更新提示适配调研.md)。

v1.2.2 起，安装包、二进制及 WebUI 记录 `releaseChannel=stable|preview`。允许数字版本更高的版本，以及同数字版本的“预览 → 正式”；拒绝数字降级及“正式 → 同版本预览”。同版本正式包的构建序号更高，后台同时核对 ZIP 内模块 ID、版本、渠道、构建序号、CRC 与 SHA-256，不只依赖按钮判断。

旧版未记录渠道时显示“渠道未知”，相同数字版本不再直接声称最新，也不猜测它一定是预览版。v1.2.1 用户可按普通更高版本升级到 v1.2.2。下载记录保存渠道；旧缓存渠道未知时需重新下载，安装成功后仍需手动重启。WebUI 与二进制版本或渠道不一致、无法核实引擎身份时，禁用下载和安装。

## 管理器与发布流程

`module.prop` 的 `updateJson` 指向 `releases/latest/download/update.json`，采用管理器标准的 `version`、`versionCode`、`zipUrl`、`changelog` 字段。正式版由 GitHub `latest` 选择；预览版不进入默认更新渠道。

构建时从 ZIP 内 `module.prop` 和实际 ZIP 哈希生成 `update.json` 与 `changelog.md`。`module/module.prop` 保存正式版版本和构建序号；`./build.sh` 生成正式包，`RELEASE_CHANNEL=preview ./build.sh` 生成带预览渠道标记、序号减一的预览包，预览产物位于 `dist/preview/`。后续正式版本的序号应比上一版至少增加 2。

CI 独立校验两套包：`AD_Killer_By_NFQUEUE-module` artifact 是正式包，`AD_Killer_By_NFQUEUE-module-preview` 是预览包。所有门禁通过后自动发布预览包。发布正式版时，使用同一次全绿 CI 的正式 artifact 替换对应版本的四个附件，核对 SHA-256 后才取消预览标记并设为 Latest；不能只修改 GitHub 的 `prerelease` 标记而继续使用预览 ZIP。已存在的正式版不得覆盖；新功能升级版本号与构建序号。

SHA-256 用于检查下载完整性，信任来源仍是项目的 GitHub 仓库与 HTTPS，并非独立发布签名。

## GitHub 请求失败

v1.2.1 起，更新检查与发布日志显示后端返回的 HTTP 错误，不再统一掩盖成“读取失败”。403 表示请求被拒绝，429 表示请求过多，可能与当前网络或代理共享出口的匿名 API 配额有关。真机排查可只读查看 API 响应头中的 `X-RateLimit-Remaining` 与 `X-RateLimit-Reset`，不要在日志或仓库中加入私人 GitHub Token。

“包含预览版”和最新 Release 日志使用 API；正式版检查优先读取静态 `update.json`，不依赖 API 配额。限流时可等待配额恢复或更换网络出口；关闭预览版只影响版本检查，不会解除发布日志接口的限流。不会用本地更新日志冒充远端内容，也不会因限流跳过下载校验。
