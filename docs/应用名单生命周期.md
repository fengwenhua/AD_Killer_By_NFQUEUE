# 应用名单与安装变更

本轮保持原来的“选择应用、保存名单”操作。修复的目标是：应用卸载、重装或系统重新分配 UID 后，不继续把旧编号当成这个应用。名单保留包名，卸载后不自动删掉用户的选择，重新安装后可以再次识别。

## 生效依据

- 启动、热重载和保存名单时，使用系统 PackageManager 的完整查询核实包名与 UID。`app_uids.conf` / `app_intercept_uids.conf` 仅是保存时的诊断缓存；守护不会用缓存代替核实。缓存损坏或过期不应授权错误的 UID。
- 非空名单在守护运行期间每 30 秒核实一次。只比较已选包名的实际映射，安装无关应用不重载规则或重写生效回执。空名单不启动查询。
- 映射发生变化时，走现有的配置修订号、规则候选、双栈路由切换和精确回执流程。新的用户保存优先；未提交的保存不会被后台检查自动提交。
- 查询失败、超时、输出不完整或身份存在冲突时，不解释成“名单为空”。已运行的守护保留此前策略，概览显示失败回执，随后定期重试；启动阶段无法核实时拒绝接管。重复同一错误不每次写日志和回执。
- 未安装的包名保留选择，其旧 UID 从新策略中移除；旧 UID 被其他应用复用时，不继承原应用的名单身份。共享同一 UID 的应用仍会一起受到影响，保存结果返回额外受影响应用数和未安装数，并在界面操作记录中提示。

安装变更的自动发现存在约 30 秒轮询间隔，另加有界查询与重载耗时。已有连接继续遵循已有 connmark 判定；本轮没有清空系统 conntrack，也不承诺立刻改变已有长连接。

## 多用户与分身的边界

现有包名名单沿用主用户（user 0）语义，本轮不新增工作资料、分身或用户选择器。同一个包名返回多个用户的 UID 时，完整解析、分别识别，只有主用户 UID 能进入现有名单；不能把其他用户 UID 取余当作主用户应用，也不默默扩展到所有用户。

目录解析兼容系统 `android` 包及厂商单段资源包，应用选择键仍保持原格式。AOSP 的 [PackageParser](https://android.googlesource.com/platform/frameworks/base/+/c86a420c6ec3eeccfa1bae8b3d99c2df769a0d2b/core/java/android/content/pm/PackageParser.java) 对 `android` 有专门例外；厂商单段记录则由当前手机的只读查询确认，并以通用固定样本补回归。

这是一项身份边界约束，不是已完成所有手机分身实现的兼容性认证。当前 PKH110 的一次完整只读包目录已送入实际 C++ 解析器并通过，未保存或打印应用名单；仅看到主用户目录，其他用户矩阵由固定样本覆盖。Android 真机安装、重装、共享 UID 和分身行为仍需后续独立验收。

实现依据：AOSP 的 [PackageManagerShellCommand](https://android.googlesource.com/platform/frameworks/base/+/android-13.0.0_r24/services/core/java/com/android/server/pm/PackageManagerShellCommand.java) 按包名聚合多用户 UID，`list packages -U --user all` 可能输出逗号分隔的 UID；[UserHandle](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/core/java/android/os/UserHandle.java) 定义用户与应用编号的组合规则。没有 UID 的记录明确标为未知身份，不能当成已卸载。

## 查询和并发约束

查询使用固定 argv，不拼 shell：先 `cmd package list packages -U --user all`，必要时尝试 `pm list packages -U --user all`。两者共用 4 秒和 8 MiB 输出额度，单次最多 2 秒，子进程回收另受既有 200 毫秒预算约束；限制记录数、行长和 UID 范围。拒绝负数、溢出、重复冲突、额外错误文本、嵌入 NUL、截断和未确认退出的子进程。遇到超时、溢出、取消或未确认的进程组，不再接着发起第二次查询。

Binder 查询不占用名单/配置写锁。保存前后复核范围和名单修订号，查询期间发生的新保存会使旧请求返回 `superseded`，不覆盖新缓存。守护查询可由暂停、退出和卸载取消；子进程继承操作租约，沿用有界进程组清理与回收机制。

## 验证入口

- `STRICT=1 make test`：目录解析、主用户边界、重装/复用、共享 UID、缺失或未知身份、稳定修订号、查询额度及子进程取消；前端提示仅接受已确认结果和合法计数。
- `make test-sanitize`：同一主机用例的 ASan/UBSan 检查。
- `sudo env CXX=clang++ make test-engine-integration`：真实 CLI、回执、iptables、NFQUEUE 与 IPv4/IPv6 流量；仅 PackageManager 边界由专属临时目录提供固定样本。新增用例使用生产的 30 秒轮询间隔，检查启动忽略旧缓存、周期重装/卸载/编号复用、查询未知及恢复、无关应用不重载、保存竞争和暂停取消。nft 与 legacy 分别运行。

以上 Linux 用例不能替代手机 PackageManager 权限、厂商分身和长时间运行验收。开发验证不会安装或改变已连接手机上的模块。
