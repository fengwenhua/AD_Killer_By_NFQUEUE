# KernelSU 软重启与守护生命周期

## 本次故障原因

2026-10-22 的设备记录显示：11:05:09 KernelSU 执行 `SoftReboot`，11:05:12 `netd` 重新启动。独立的旧 AD Killer 守护未退出，仍运行已被替换的 v1.2.2 映像，而安装文件已是 v1.2.3。

双栈 `ADK_NFQ_ENTRY` 都没有 OUTPUT 引用，队列依然绑定旧守护但没有新流量；指标的更新时间继续刷新，包数和拦截数不变。原启动脚本在 `autostart=false` 时立即退出，未处理软重启幸存的进程，因此出现“进程活着、路由失效”的半运行状态。

KernelSU 对应版本在停止 Android 用户态服务之前执行 `emulated-soft-reboot` 钩子，然后重新运行启动阶段。这给模块提供了先释放自身资源、再按策略启动的生命周期边界。[KernelSU 官方软重启实现](https://github.com/tiann/KernelSU/blob/46636100/userspace/ksud/src/soft_reboot.rs)

## v1.2.4 修复

- `emulated-soft-reboot.sh` 在用户态重启前调用 `--prepare-reboot`，只优雅停止已验证身份的本模块守护；由守护自己释放队列、路由和生命周期锁。
- `service.sh` 在判断自启策略前再次执行幂等清理，兼容从没有软重启钩子的旧包升级。无实例时不写配置、不创建数据目录、不清理防火墙。
- 生命周期停止不是用户暂停：不修改 `enabled`、`manual_stop`、`autostart`，不发 SIGKILL；退出超时则报错，启动脚本不再创建第二个实例。
- 开机自启关闭或用户已暂停，冷启动／软重启后均不启动。开启自启且未暂停，等待 `sys.boot_completed=1` 后才启动；等待超时或期间关闭开关则退出。
- `--status-fast` 读取双栈 OUTPUT，要求恰好一个稳定入口且没有旧式直接跳转；`route_check=entry` 不等同于完整链校验。`--status` 执行完整校验，两者均不再因查询而修改防火墙。
- 状态额外报告守护 PID 及 `daemon_image_current`，用文件身份判断正在运行的映像是否与查询二进制相同，不因 argv 路径相同就当作新版本。
- 概览轮询会把丢失入口或旧映像降级为可见提示，完整校验失败／不可读时不保持绿色；恢复正常也必须完整校验。页面不自动重启守护或插入路由。
- 用户点击“启动守护”时，即使旧路由仍健康，只要映像不同，也会优雅切换到当前二进制；继续保留超时保护和外部队列保护。

## 已安装旧版如何恢复

在 WebUI 点击“启动守护”可触发 v1.2.3 已有的缺失路由恢复逻辑，或先暂停再启动。不要手动往 OUTPUT 插一条跳转就算修复，否则旧映像和队列归属没有核实。

重启守护会重置“本次守护”统计，不删除规则、来源或应用名单。升级到修复版后，若自启关闭，软重启后手动启动属于预期行为。

## 验证边界

主机／浏览器测试覆盖策略保持、超时、旧映像识别、入口缺失及界面恢复；一次性 Linux 内核测试覆盖真实队列、双栈路由和外部规则保留。真机恢复使用独立路由检查与计数增长，不以快速状态的旧版近似值代替证据。

没有为验证而对用户手机执行整机或软重启。其他管理器忽略 KernelSU 专用钩子，仍可由标准启动脚本完成旧实例清理。
